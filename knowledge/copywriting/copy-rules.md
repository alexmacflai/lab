# Copy rules

- Apply these rules to headings, descriptions, instructions, buttons, placeholders, errors, accessible labels and README/index copy, including strings embedded in HTML or JavaScript.
- Write in British English. Use sentence case for interface labels and headings; preserve proper names and deliberate typographic treatment within a piece.
- Use plain words and specific nouns. Remove inflated claims, empty superlatives, unnecessary setup and repetitions that obscure the point.
- Keep supported details and uncertainty. Do not invent statistics, experiences, capabilities or promises to make text more vivid.
- Name the action on buttons and the destination on links. Match wording to actual behaviour: archive, hide and delete are different actions.
- State failures plainly and offer only next steps the prototype supports. Placeholders must describe the current state without invented availability dates.
- Do not add text to fill a layout or write a sentence that only restates its heading.
- Keep terms consistent within each prototype. Different pieces need not share labels for different concepts.
- Preserve exact supplied or approved wording and attributed quotations. Flag suspected errors separately instead of silently correcting them. When revision is requested, edit only the authorised text; quotations remain exact unless explicitly authorised otherwise.
- Follow [voice and tone](voice-and-tone.md) and [humanise-copy](../../.agents/skills/humanise-copy/SKILL.md). Clear existing copy may pass unchanged.
