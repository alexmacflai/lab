# Glossary

The framework's own terms. The project's product vocabulary belongs in `product/glossary.md`.

- **Adapter:** a tool entry file or link that exposes `AGENTS.md` and `.agents/skills/` to a particular agent tool, such as `CLAUDE.md`.
- **Domain:** a field of work matching an industry role and skillset, such as design, engineering, copywriting or marketing, with its own guidance and vocabulary. Reports, specs and project-wide documents are not domains.
- **Entry point:** the file readers start from, such as `AGENTS.md` or a folder README.
- **Kind:** a file's purpose: instruction, doc, skill, spec or report; see [kinds.md](kinds.md).
- **Module:** an optional part of the structure, such as specs or reports, added when the project needs it.
- **Project fill-in:** content the project supplies in the file where it belongs; a fill-in comment marks its place until then.
- **Registry:** the list of permitted values, such as the tags in [tags.md](tags.md).
- **Routing table:** a table that leads readers to files: the root one in `AGENTS.md` points common tasks to guidance and skills; each folder README's generated one lists the folder's files and subfolders.
